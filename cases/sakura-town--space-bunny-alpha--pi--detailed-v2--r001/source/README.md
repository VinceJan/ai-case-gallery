# 樱花小镇 · Sakura Town

> 一个用 **Three.js + Vite** 从零构建的 3D 日式乡镇生活模拟游戏。
> 晚春，樱花季。一个被低山、溪流与杉林围住的小镇，一条铁路从中穿过。

```bash
npm install
npm run dev      # http://127.0.0.1:5273
npm run build
```

---

## 一、这是什么

一座**规模不大、密度较高、风格统一**的小镇。你从车站前开始，在告示板和街坊那里接到一桩桩小事，
替他们跑腿、找东西、送东西，于是一天天地和这里的人熟起来。

- **一条铁路**贯穿全镇，列车真的会进站、减速、开门、停靠、关门、离开。
- **一道道口**与列车联动：铃响 → 栏杆落下 → 行人等待 → 列车通过 → 栏杆抬起。
- **五位核心居民**有各自的名字、住处、作息、习惯和喜好。背景居民维持街上的生活感。
- **五处可进入的室内**：便利店 / 喫茶店 / 车站站厅 / 一户住宅 / 町内集会所。
- **一条核心玩法循环**：接下「町内便」——替人跑腿，攒下信任，解锁新的地点与事件。
- **昼夜与雨**：光、影子、店铺招牌、窗户、路灯、月台、居民行为都会跟着变。

风格统一采用 cel-shading（卡通渲染）、柔和而清晰的配色与适度轮廓线。

## 三、小镇的构成

### 地形与边界
世界是一个**平面 3D 盆地**。高度场由解析函数生成：中央是缓坡的町内，四周被山体包围，
东侧有一条从山里流下来的溪。道路、建筑地基、铁路路堑都是在同一张高度网格上做的
「切填」，所以路基是平的，山坡是自然的。玩家走不上去的陡坡、山林、溪流与两条隧道口
共同构成边界——没有一堵空气墙。

### 区域
- **车站与月台** —— 小镇的大门。铁轨、道口、时刻表、站务室、自动售货机。
- **商店街** —— 主街两侧：樱花便利店、喫茶ひより、小料理ます、和菓子花の国、杂货店、邮局、诊所、公寓。
- **住宅区** —— 十几栋町宅，晾衣绳、邮箱、自行车、盆栽、空调外机。
- **河童公园** —— 沙坑、滑梯、秋千、喷泉、池子、樱花林。
- **绯樱神社** —— 鸟居、石灯笼、注连绳、手水舍、绘马板。见晴台在神社后坡。
- **学校与集会所** —— 镇子西侧。
- **东边的林子** —— 小桥、溪边水车、废弃的旧屋、铁路隧道口。

### 铁道
列车沿一条缓弯轨道运行，**时刻表与站内贴图里的时刻一致**。
进站前先能听见远处的汽笛与隆隆声；道口提前报警、落杆；列车停稳后开门、上下客、再关门离开。
NPC 会在月台上等车、避让列车、也可能在道口前停住。

### 居民
五位核心居民：**藤田阳子**（便利店）、**小林健**（站务员）、**森澄**（大学生 / 喫茶店）、
**野上源一**（退休教师）、**高橋遥**（高中生）。他们按时钟在镇上移动，
进入室内时是真的走进了室内。另有四组背景居民按时间段往返于车站、商店街、住宅与公园。
好感度共 5 级，会改变对话内容与愿意告诉你的事。

### 玩法循环
1. 在**车站的告示板**或居民处接到「町内便」。
2. 跑腿：买东西、找失物、把东西送到某个人手里、去某个地方。
3. 完成 → 报酬 + 好感度 + 新的对话与新的委托。
4. 沿途**发现**神社、见晴台、水车小屋、林间旧屋、隧道口、集会所……
5. 第十件委托之后，小镇祭的序幕。

另外每天的告示板上还有一条随机的**町内会通知**，帮街坊完成会有好事发生。

### 小事
这些不起眼的东西撑起了「有人生活」的感觉：
道口的警铃会响两声再停；火车进站前先在山那边传来声音；居民回家以后窗户亮灯；
店铺打烊后招牌熄灭；便利店的自动门会真的滑开；雨一下大，街上的人都撑起了伞；
水车一直在转，公园的时钟和车站的时钟走的是同一条时间。

## 四、技术结构

纯 **Three.js**，不依赖任何游戏引擎；没有额外的运行时依赖，只有 `three` 与 `vite`。

```
src/
  main.js               启动 / 载入 / 标题画面
  core/
    game.js             主控：装配、每帧调度、存档
    input.js            键鼠输入
  entities/
    player.js           玩家控制（移动 / 碰撞 / 姿态）
    camera.js           第三人称相机（轨道 / 避障 / 室内边界）
    character.js        统一风格的低模人形与程序化动画（含雨伞）
    npc.js              居民：作息、寻路、区域切换、对话姿态
  world/
    layout.js           ★ 唯一数据源：道路 / 建筑 / 地标 / 锚点 / 时刻
    terrain.js          解析高度场 + 溪流侵蚀 + 道路切填 + 地形网格
    roads.js            路面、人行道、标线、斑马线、小桥
    railway.js          轨道、月台、隧道口、道口设备、列车、道口联动
    building.js         参数化建筑生成器（屋顶 / 窗 / 招牌 / 店面内景）
    interiors.js        五处室内空间
    furniture.js        家具套件
    props.js            树木、路灯、自贩机、自行车、长椅、鸟居、石灯笼…
    instancing.js       静态道具按「材质 × 空间分块」合并
    geom.js             几何构造（GeoBuf / 屋顶 / 台阶 / 低模球）
    navgraph.js         步行导航图 + A*
    sky.js              天空、太阳月亮、星星、云、昼夜光照
    town.js             总装：把上面所有东西摆进世界里
  render/
    toon.js             渐变贴图、共享材质、轮廓线（反向外壳）
    textures.js         程序化贴图（木壁板、屋瓦、沥青、招牌、时刻表、自贩机…）
    palette.js          全局色板
  systems/
    time.js             时间与时段
    weather.js          晴 / 阴 / 雨（含雨幕与灯光影响）
    collision.js        碰撞世界（旋转盒 / 圆柱 / 坡度与台阶判定）
    zones.js            世界 ⇄ 室内 的切换
    interaction.js      就近 + 面朝方向的交互选取
    inventory.js        道具与金钱
    quest.js            委托、地标发现、每日告示板
    events.js           少量随机事件
    audio.js            程序化音效与环境音
  data/
    npcData.js          居民数据（外形 / 作息 / 喜好 / 台词）
    dialogue.js         对白生成
  ui/
    hud.js              HUD / 对话 / 手帐 / 地图 / 町民 / 设置
    style.css
```

### 几个实现要点
- **地形与碰撞共用同一份高度数据**：`heightAt()` 既是玩家脚下的地面，也是道路网格、
  道具摆放的依据，所以不存在「看起来浮空」的问题。
- **静态道具不_instancing_**：每种道具、每块空间分块、每种材质合并成一个静态 Mesh，
  既省 draw call，又能被视锥剔除。
- **轮廓线**用反向外壳（BackSide + 视空间法线外扩），屏幕宽度恒定。
- **室内**放在世界远处的偏移坐标，与外部通过门互相传送；相机在室内被限制在房间范围内。
- **音频**全部用 WebAudio 现场合成：汽笛、道口铃声、门铃、雨、风、虫鸣、溪水、脚步。

## 五、开发过程中守住的优先级

按「先做完，再做大」的原则推进：

1. 基础可玩（移动、碰撞、相机、地形）
2. 视觉成立（街区、材质、光照）
3. 世界开始动（列车、道口、居民）
4. 真正形成玩法（交互、���内、主循环）
5. 增加生活感（昼夜、事件、声音、细节）
6. 有余力才扩展

在遇到冲突时，**一律选择完成度而不是规模**：宁可只有几栋能真正走进去的房子，
也不做十栋进不去的空壳；宁可少几个系统，也要把已有的系统连起来。

## 六、已知取舍

- 不含战斗、经营、建造、农业、多人联机等大型系统——这是刻意的。
- 背景居民没有复杂的规划器，只做按时段往返的简单行为，用来补生活感。
- 天气是可选增强，只做了雨天（画面、雨声、路面氛围、居民撑伞），没有做雪与台风。
- 音效是程序化合成而非采样，追求「有存在感」而不是高保真。
