# 樱花小镇 — 开发进度与决策记录

> 项目代号 `sakura_town` · Three.js + TypeScript + Vite · 全程序化生成，无外部资源依赖

## 意图与约束

- 从零构建一个紧凑、闭环的日式乡镇生活模拟：晚春樱花期、当代日本地方小镇、
  轻怀旧动画背景式 cel/toon 美术。
- 优先完成度：更小、更密、更完整；建筑尽量可进入；NPC 有住所、关系、作息与有限决策；
  交通/商店/物品/昼夜天气/随机事件/玩家行为互相影响并持久化。
- 只用浏览器成熟轻量 3D 路线（three.js），世界由代码生成，不依赖 Blender 等外部 DCC。
- 所有 gameplay 随机性走 seeded RNG（`src/utils/random.ts` 的 `Rng` 类，可序列化进存档）。

## 架构决策

| 决策 | 理由 |
| --- | --- |
| 室内=同一场景中 y=-1000 的独立区域，间距 420m，靠相机 far=320 互相屏蔽 | 避免第二场景/加载开销；进出建筑=传送+碰撞场切换 |
| 建筑/道具用 MeshBuilder 合并为单网格 + 顶点色 + MeshToonMaterial（3 阶梯度贴图） | 每栋建筑 1 个 draw call，保留 cel/toon 色阶观感 |
| 樱花树/松树/路灯用 InstancedMesh + instanceColor | 全场树木 2-4 个 draw call |
| NPC 移动 = 路网图 BFS 寻路（`src/world/pathfind.ts`）+ 作息表 + 效用决策 | 小镇规模下足够且确定性可复现 |
| 相机 = 第三人称跟随 + AABB 射线避让（拉近并抬高） | 住宅密集区不穿墙 |
| 音频 = WebAudio 程序化合成（风声/雨声/虫鸣/鸟鸣/列车/UI/烟花） | 零外部资源、离线可玩 |
| 存档 = localStorage JSON（含 RNG 状态） | 睡眠推进与每小时自动存档 |

## 已修复的关键缺陷（开发中发现）

1. 阴影相机改视锥后未 `updateProbleMatrix()` → 全局阴影痤疮（画面死黑）。
2. 玩家出生点在房屋碰撞体内 → 相机在墙内（开场纯色画面）。
3. NPC 室内→户外路径从内景坐标起算 → NPC 跑飞到 (3354,-998)。
4. 不可进入建筑的 NPC 被放到地图原点 → 应放入隐藏内景坐标。
5. `teleport(x,z,y)` 参数顺序错误 + 进入内景丢失 Y 坐标 → NPC/玩家错位 1000 米。
6. 快速点按 E 因 keydown/keyup 同帧而丢失 → 改按键队列。
7. 交互解析先于移动导致"刚到门口按 E 无效" → 调整更新顺序。
8. 天气变暗被每分钟 `applyLighting()` 重置 → TimeSystem 记住 weatherDim。
9. 平交道口一个接近全部落栏 → 改每口独立判断（列车前端 +34m）。
10. 屋顶斜面几何交叉成 X + 山墙未封堵 → 重写 addGableRoof。
11. NPC 访客与店主堆叠同一锚点 → 访客使用顾客区锚点。
12. 室内相机贴墙 → 室内切换为房间概览相机。

## 复现与部署

```bash
npm install
npm run dev        # 开发服务器 http://127.0.0.1:5188
npm run build      # 生产构建 → dist/
npm run preview    # 预览构建 http://127.0.0.1:4188
npx playwright test          # 视觉 + bot playtest
```

静态部署：`dist/` 为纯静态产物（相对路径），可托管到任意静态服务器。
